# API

Этот сервис можно вызывать из своего кода: спросить по документам, найти
фрагмент без модели, загрузить файл, посмотреть источники. Два диалекта на один
и тот же движок.

| | когда брать |
|---|---|
| **Нативный** `POST /api/v1/answer` | своя интеграция: нужны сноски, шаги агента и стоимость запроса |
| **OpenAI** `POST /api/v1/chat/completions` | готовый SDK, n8n, LangChain, LibreChat, плагин редактора — работает по `base_url` |

Интерактивная документация со всеми схемами — `GET /api/docs`
(OpenAPI: `/api/openapi.json`).

`/api/v1` — это контракт: форма ответов не меняется, а изменение, которое её не
сохраняет, станет `/api/v2`. Остальные ручки под `/api` написаны для нашего же
интерфейса, ходят в них на свой риск.

## Аутентификация

Тот же JWT, которым входят в интерфейс, в заголовке `Authorization: Bearer`.

```bash
cd backend && uv run rag-token --email вы@example.com --days 365
```

```bash
curl -H "Authorization: Bearer $TOKEN" https://ваш-хост/api/v1/me
# {"user_id":"db8122ef-4ce8-4dce-a3d4-d6b0ab53cf08"}
```

Токен — это и есть пользователь: всё, что видно по нему, принадлежит одному
человеку, и фильтр по `user_id` уходит в сам индекс. Отозвать токен досрочно
нельзя (проверка подписи не ходит в базу), поэтому для интеграции лучше
выпустить отдельный, с тем сроком, который вам нужен.

`GET /api/v1/me` — самый дешёвый способ проверить, что токен ещё жив.

## Спросить

### `POST /api/v1/answer`

```bash
curl -X POST https://ваш-хост/api/v1/answer \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"question": "сколько дней отпуска по политике?"}'
```

```json
{
  "answer": "Основной отпуск — 28 календарных дней [1].",
  "citations": [
    {"n": 1, "document_id": "0f0f9d3c-…", "filename": "Политика.pdf",
     "page": 3, "url": null, "snippet": "28 календарных дней…"}
  ],
  "steps": [{"tool": "search_knowledge", "query": "отпуск дней политика"}],
  "usage": {
    "prompt_tokens": 5000, "completion_tokens": 60, "total_tokens": 5060,
    "cost_usd": 0.00059, "cost_complete": true, "calls": 2,
    "stages": [
      {"stage": "rerank", "model": "google/gemini-2.5-flash-lite", "calls": 1,
       "prompt_tokens": 900, "completion_tokens": 12, "cost_usd": 0.00017},
      {"stage": "answer", "model": "openai/gpt-5-mini", "calls": 1,
       "prompt_tokens": 4100, "completion_tokens": 48, "cost_usd": 0.00042}
    ]
  },
  "took_ms": 4310,
  "chat_id": null,
  "message_id": null
}
```

**Запрос**

| поле | по умолчанию | что делает |
|---|---|---|
| `question` | — | вопрос, 1–8000 символов |
| `stream` | `false` | `true` — server-sent events вместо одного JSON |
| `web` | `false` | разрешить агенту искать в интернете, когда в документах ответа нет |
| `chat_id` | `null` | продолжить сохранённый диалог: история подгрузится, вопрос и ответ запишутся |
| `history` | `[]` | или ведите историю сами: `[{"role":"user"\|"assistant","content":"…"}]` |

`chat_id` и `history` вместе — 422: это два диалога, называющих себя одним.
Своя история обрезается до последних 20 сообщений — столько же получает
интерфейс, и это то, чем ограничена цена хода.

**Ответ**

| поле | что это |
|---|---|
| `answer` | текст. Сноски в нём — `[1]`, `[2]`, нумерация совпадает с `citations` |
| `citations` | только те источники, на которые ответ действительно ссылается. Пустой список — ответа в базе нет, и это факт о выдаче, а не мнение модели |
| `steps` | что агент делал, по порядку. Два поиска подряд означают, что первый ничего не дал |
| `usage` | токены и деньги, [ниже](#стоимость) |
| `took_ms` | сколько ждал вызывающий |
| `chat_id`, `message_id` | заполнены, только если вопрос задан в сохранённый чат |

Сноска бывает и на страницу из интернета — тогда `document_id` пустой, а `url`
заполнен. У фрагмента из базы наоборот: ссылку на оригинал даёт
[`/documents/{id}/link`](#документы), который умеет её подписать.

### Потоком

`{"stream": true}` — тот же ответ как `text/event-stream`. Данные каждого
события — JSON.

| событие | данные |
|---|---|
| `step` | `{"tool": "search_knowledge", "query": "…"}` — приходит дважды: сначала имя инструмента, затем запрос, как только он разобрался |
| `token` | строка с куском ответа |
| `citations` | итоговый список источников |
| `usage` | объект `usage` целиком |
| `done` | **весь ответ одним объектом** — тот же JSON, что вернул бы `stream: false` |
| `error` | строка. Ход не удался; `done` после него не будет |

Последнее событие — это и есть весь ответ, поэтому клиент может не собирать
токены вручную: показывайте их для скорости, а читайте `done`.

```python
import httpx, json

with httpx.stream("POST", "https://ваш-хост/api/v1/answer",
                  headers={"Authorization": f"Bearer {token}"},
                  json={"question": "что у меня по проекту?", "stream": True},
                  timeout=180) as response:
    event = None
    for line in response.iter_lines():
        if line.startswith("event: "):
            event = line[7:]
        elif line.startswith("data: "):
            data = json.loads(line[6:])
            if event == "token":
                print(data, end="", flush=True)
            elif event == "done":
                print("\n", data["citations"], data["usage"]["cost_usd"])
```

## Найти без модели

### `GET /api/v1/search`

Десятая доля секунды и ноль токенов — против секунд и счёта через `/answer`.
Говорит, где написано; никогда не объясняет и не пересказывает.

```bash
curl -G https://ваш-хост/api/v1/search -H "Authorization: Bearer $TOKEN" \
  --data-urlencode "q=вишлист" --data-urlencode "limit=5"
```

```json
{
  "hits": [{"document_id": "0f0f…", "filename": "Заметки.md", "page": null,
            "snippet": [{"text": "добавил в ", "hit": false},
                        {"text": "вишлисте", "hit": true},
                        {"text": " наушники", "hit": false}]}],
  "found": 20,
  "took_ms": 96
}
```

| параметр | что делает |
|---|---|
| `q` | запрос, 1–500 символов |
| `limit` | 1–50, по умолчанию 20 |
| `source` | UUID источника: искать только в нём (уходит в сам индекс) |
| `days` | 1–3650: только документы, изменённые за последние N дней |

`snippet` приходит уже разрезанным на куски с флагом `hit` — правило, что
считать совпадением, живёт на сервере, а клиенту не нужно класть в DOM
ничего, кроме текста. `found` — сколько индекс предложил до отбора: «3 из 20» говорит,
что поиск работал.

`503` означает, что индекс сейчас перестраивается (обычно 6–7 секунд после
подключения источника), а не что запрос неверный.

## Документы

| | |
|---|---|
| `GET /api/v1/documents` | всё, что доступно для поиска: и загруженное, и из подключённых источников |
| `POST /api/v1/documents` | загрузить файл (`multipart/form-data`, поле `file`) |
| `GET /api/v1/documents/{id}/link` | где открыть оригинал |
| `DELETE /api/v1/documents/{id}` | удалить загруженный файл |

```bash
curl -X POST https://ваш-хост/api/v1/documents \
  -H "Authorization: Bearer $TOKEN" -F "file=@Политика.pdf"
```

```json
{"id": "0f0f9d3c-…", "filename": "Политика.pdf", "mime_type": "application/pdf",
 "size_bytes": 184320, "created_at": "2026-09-07T10:00:00Z", "status": "processing",
 "source_id": "…", "source_name": "Загруженные файлы", "removable": true,
 "text_layer": true}
```

Форматы: `.pdf`, `.docx`, `.pptx`, `.xlsx`, `.txt`, `.md`; до 64 МБ. Что-то
другое — `415` сразу, а не документ, который навсегда остался бы в статусе
«индексируется».

`status` читается прямо из индекса, а не из базы: `ready` значит, что документ
действительно находится поиском, а не что его приняли. Обычно это несколько
секунд. `text_layer: false` — это PDF без текстового слоя, то есть скан: он
загрузится и будет считаться готовым, но не найдётся никогда.

`removable: false` — документ из подключённого источника: удалять его нужно
там, где он лежит, а `DELETE` вернёт `404`, потому что следующий опрос всё
равно принёс бы его обратно.

## Источники

`GET /api/v1/sources` — подключённые источники и то, что индексер видел в них
последним.

```json
[{"id": "…", "kind": "s3", "name": "Договоры", "created_at": "…",
  "status": "ok", "problem": "", "checked_at": "2026-09-07T09:58:12Z", "documents": 42}]
```

`kind` — `gdrive`, `notion`, `yandex`, `dropbox`, `onedrive`, `s3`.
`status` — `ok`, `error` или `unknown`; последнее до первой проверки, и никогда
не `ok`: источник, который никто не читал, — это не работающий источник. При
`error` в `problem` лежит причина одной фразой (текста исключения там не бывает
— в нём попадаются внутренние адреса и сам токен).

Подключение и отключение источников — только через интерфейс: там пошаговые
инструкции под каждым видом, а `POST` с чужими учётными данными по HTTP из
скрипта не то, что стоит делать удобным.

## Чаты

Нужны, только если вы хотите, чтобы историю хранили мы.

| | |
|---|---|
| `POST /api/v1/chats` | создать — вернёт `id` для `chat_id` в `/answer` |
| `GET /api/v1/chats` | список, новые сверху |
| `GET /api/v1/chats/{id}/messages` | конец чата, страницами по 50; `next_cursor` → `before` для страницы постарше |
| `DELETE /api/v1/chats/{id}` | удалить вместе с сообщениями |

```bash
CHAT=$(curl -sX POST https://ваш-хост/api/v1/chats -H "Authorization: Bearer $TOKEN" | jq -r .id)
curl -X POST https://ваш-хост/api/v1/answer -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d "{\"question\": \"а что там по срокам?\", \"chat_id\": \"$CHAT\"}"
```

Заголовок чата ставится из первого вопроса. Без `chat_id` не сохраняется ничего
— это и есть режим по умолчанию.

## Формат OpenAI

```python
from openai import OpenAI

client = OpenAI(base_url="https://ваш-хост/api/v1", api_key=TOKEN)

answer = client.chat.completions.create(
    model="grounded",
    messages=[{"role": "user", "content": "сколько дней отпуска?"}],
)
print(answer.choices[0].message.content)
print(answer.usage.model_extra["cost"], answer.model_extra["citations"])
```

Проверено официальным клиентом `openai`: список моделей, обычный и потоковый
ответ, а `404` и `401` приходят как родные `NotFoundError` и
`AuthenticationError`.

| | |
|---|---|
| `POST /api/v1/chat/completions` | `stream` работает как у OpenAI: чанки, затем чанк с `usage` и пустым `choices`, затем `data: [DONE]` |
| `GET /api/v1/models` | `grounded` и `grounded-web` |

**`model` — это переключатель.** Фиксированный протокол не даёт передать наши
флаги, но имя модели даёт всегда: `grounded` отвечает по документам,
`grounded-web` может ещё и поискать в интернете. Любое другое имя — `404`, а не
молчаливая подмена.

**Что теряется в переводе, осознанно:**

- **Системное сообщение от вызывающего игнорируется.** Наш промпт — это то, что
  держит ответ на документах и нумерует сноски; дать его заменить значило бы
  превратить сервис в модель общего назначения, которая что-то там читала.
- **`temperature`, `top_p`, `max_tokens` и прочее принимаются и игнорируются.**
  Один ход — это несколько вызовов модели плюс поиск; выполнить такой параметр
  наполовину хуже, чем не выполнять вовсе. Ошибки на них нет: SDK их посылает
  всегда, и `422` сделал бы эндпоинт бесполезным ровно для тех клиентов, для
  которых он существует.
- **Вопрос — это последнее сообщение от пользователя**, а не последнее
  сообщение: клиент, который дослал реплику ассистента, продолжает диалог, чей
  вопрос по-прежнему выше.
- **Сноски приходят в поле `citations`** рядом с `choices` — так же, как это
  делают Perplexity и OpenRouter. Клиент, который его не читает, всё равно
  покажет связный ответ: `[1]` и `[2]` стоят в самом тексте.
- **Стоимость — в `usage.cost`**, расширение OpenRouter к тому же объекту.
  Разбивка по этапам есть только в нативном `/answer`.
- **Ошибки — в форме `{"error": {...}}`** на этих двух путях (и только на них:
  `/api/v1/chats` начинается так же, но отвечает как весь остальной API).
  Обрыв потока после его начала — это `finish_reason: "length"` и `[DONE]`:
  своего кадра для ошибки протокол не предусматривает, и «ответ не закончен» —
  честное его прочтение.

## Стоимость

`usage` — это не оценка по таблице цен, которая устареет. Каждый платный вызов
идёт через OpenRouter, а тот присылает цену завершения в своём `usage`
(замерено: `cost` приходит и без флага `usage: {include: true}`), и сумма
собирается по вызовам.

| поле | |
|---|---|
| `cost_usd` | доллары, сумма того, что выставил провайдер |
| `cost_complete` | `false`, если какой-то вызов цену не сообщил — тогда `cost_usd` это нижняя граница, а не счёт |
| `calls` | сколько платных вызовов сделал ход |
| `stages` | те же числа по этапам: `answer` (сам агент), `rerank` (отбор релевантного за каждым поиском), `web_search` |

Разбивка обычно и есть самое интересное. Замерено: отбор релевантного — около
`$0.00017` за вызов, поиск в сети — около `$0.00125`, то есть один поход в
интернет дороже, чем всё остальное в коротком ответе. Поэтому `web` выключен по
умолчанию и ограничен отдельным потолком.

Один запрос ограничен сверху и без квот: не больше 3 поисков по базе, 2 в сети,
6 вызовов инструментов и 8 вызовов модели за ход, плюс общий таймаут. Сбежать
со счётом один вызов `/answer` не может.

## Ошибки

`{"detail": "…"}` — везде, кроме двух путей OpenAI, где `{"error": {...}}`.

| код | что значит |
|---|---|
| `400` | пустой вопрос, пустой файл, имя файла без имени |
| `401` | нет токена, не наша подпись, истёк. Заголовок `WWW-Authenticate: Bearer` |
| `404` | нет такого чата, документа или модели — или он не ваш: какие id существуют, знает только владелец |
| `413` | файл больше 64 МБ |
| `415` | формат, который мы не читаем |
| `422` | тело не проходит валидацию (`detail` — список полей) |
| `502` | ход не удался. Причина — в логах сервера, не в ответе: в тексте таких ошибок бывают внутренние адреса и ключи |
| `503` | индекс перестраивается — только у `/search` |
| `504` | модель не ответила за отведённое время |

## Чего здесь нет

- **Нет ограничения частоты запросов и квот на токен.** Один ход ограничен
  (см. выше), поток запросов — нет. Токен — личный ключ на личной установке;
  утёкший может тратить деньги в цикле. Помечено в коде `ponytail:` с ценой
  исправления.
- **`/answer` не принимает фильтр по источнику.** Агент сам решает, когда
  сузить поиск по дате (по формулировке вопроса), а явные фильтры есть у
  `/search`. Прикрутить их к каждому инструменту агента — отдельная работа,
  которую пока никто не просил.
- **Подключение источников только через интерфейс** — см. выше.
- **CORS закрыт** для всех, кроме `CORS_ORIGINS` из `backend/.env`. API
  рассчитан на вызов с сервера: браузерная интеграция потребует добавить туда
  свой origin, а вместе с ним — подумать, где будет лежать токен.
